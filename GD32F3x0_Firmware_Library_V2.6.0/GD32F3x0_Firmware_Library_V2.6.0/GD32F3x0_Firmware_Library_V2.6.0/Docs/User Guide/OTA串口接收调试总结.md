# GD32F330 OTA 串口接收调试总结

## 一、背景与结论

- 目标：打通 **OTA 闭环**（上位机 0xF0 开始 → 0xF1 分包写入 → 0xF2 结束 → 重启 Bootloader 安装）。
- 现象：**F0 有回复，但 F1（518 字节数据帧）无回复**，或回复"写入失败 / frame length too short"。
- **结论：链路已打通并验证**——F1 能正常写入下载区并回复 `55 03 F1 00`。

最终确认：**真正的主因是变量类型截断**（`uint8_t` 装不下 518，详见《变量类型与截断详解.md》）；并澄清了曾被误判的 **"DMA 单次模式地址未重置"** 论断（不成立，见下文 3.2）。

---

## 二、问题速查表

| # | 问题现象 | 根因 | 解决方式 |
|---|---|---|---|
| 1 | F1 回 **"frame length too short"** | `ota_handle_write(uint8_t *frame, **uint8_t len**)` 的 `len` 是 **uint8_t**，518 传入被截断成 **6** | `len` 参数改 **uint16_t** |
| 2 | （已澄清，非根因）F1 曾"无回复"被归咎于 DMA 地址未重置 | 业务协议 0x82→0x84 连续不同功能码从不出错，反证 **DMA 地址会重置**，原论断不成立 | 无需改动；`dma_memory_address_config` 可留可去 |

## 三、问题详解

### 3.1 uint8_t 参数截断（最隐蔽，4 号坑）

- **现象**：解析器明明 `idx=518 expect=518`（完全正确），但进 `ota_handle_write` 后 `len=6`。
- **根因**：`void ota_handle_write(uint8_t *frame, uint8_t len)` 的 `len` 是 **uint8_t**，最大只能装 255。**518 = 0x0206，被隐式截断成 0x06 = 6** → `if (len < 518)` 永远成立 → 永远 "too short"。
- **原理**：C 里函数参数按类型收窄，`uint16_t 518` 传给 `uint8_t` 参数时只保留低 8 位。
- **解决**：`len` 参数改 `uint16_t`。**凡是可能超过 255 的帧长，入参一律用 `uint16_t`。**

### 3.2 DMA 单次模式地址重置（已澄清，非根因）

- **原论断**：DMA 单次模式收完一帧后内存地址前移，ISR 重配不重置地址 → 第二帧错位。
- **反证**：**communicate_protocol 业务协议（0x82 → 0x84 连续不同功能码）从不出错**——若地址真不重置，第二个不同命令会读到残留帧而回复错命令。实践反证 **DMA 地址在重使能时会重置**，原论断不成立。
- **为何 F1 曾"加地址重置后才有回复"**：该现象与"重编 F1 定长解析器"等改动同时发生，被混淆；用调试打印逐段定位后，**唯一被证实的原因**是 `uint8_t len` 截断（`parse idx=518 expect=518`，`ota_write len=6`）。
- **结论**：`dma_memory_address_config` 是**无害的正确写法**（重设地址到基址永远安全），但**不是 F1 问题的根因**，可留可去。

## 四、排障方法学

1. **分环节定位**：把链路拆成三段——**接收**（DMA+空闲中断，看收到多少字节）→ **解析**（看帧凑满的 `idx`/`expect_total`）→ **参数传递**（看函数入口收到的 `len`）。每段加一行 debug 打印即可快速二分定位：
   ```c
   // 接收：主循环收到多少字节、开头 6 字节
   printf("rx: len=%u b=%02X %02X %02X %02X %02X %02X\r\n", ...);
   // 解析：凑满一帧的 idx 和期望值
   printf("parse: idx=%u expect=%u func=%02X\r\n", ...);
   // 参数：函数入口实际收到的 len
   printf("write: len=%u f=%02X %02X %02X ...\r\n", ...);
   ```
2. **用数据说话**：遇到"逻辑上不可能"的现象（如 `expect=518` 但 `len=6`），打印出实际数值立刻见分晓，别靠猜。
3. **大帧一律 uint16_t**：帧长超过 255 的（如 F1=518），函数入参、计数器、校验长度全用 `uint16_t`，防截断。

---

## 五、关键知识点

- **变量类型截断是主因**：518 = 0x0206，塞进 `uint8_t` 只留 0x06 = 6，C 隐式收窄不报错，最隐蔽。详见《变量类型与截断详解.md》。
- **DMA 地址重置论断不成立**：业务协议连续不同功能码正常即反证；真正的根因是类型截断。
