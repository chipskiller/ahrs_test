# GD32F330 上电启动流程与原理详解（学习笔记）

> 本文档是两段学习对话的整理：
> 1. 从上电到 App 业务循环，单片机硬件上走的完整流程；
> 2. 两个容易绕晕的概念：**SystemInit 是软件还是硬件**、**Thumb 指令集是谁指定的**。

适用工程：`ahrs_test/Template`（GD32F330，Cortex-M4，Bootloader + App 双程序）。

---

## 一、一句话总览

上电后 **CPU 自己从 Flash 头部读出"第一步该干嘛"**（向量表）→ 跑**汇编启动文件**把 C 语言环境搭好 → 进 **Bootloader 的 main** → Bootloader 关中断、切向量表、设好栈后**跳到 App** → App 重走一遍启动流程、配好所有外设 → 进入 **`while(1)` 业务循环**，靠**中断**驱动业务。

---

## 二、完整流程：从复位到业务循环

```mermaid
flowchart TD
    P0[上电<br/>电源就绪+复位释放] --> P1[硬件读向量表<br/>取栈顶MSP + 复位向量Reset_Handler]
    P1 --> P2[Reset_Handler 汇编<br/>startup_gd32f3x0.s]
    P2 --> P3[SystemInit<br/>配时钟到 84MHz]
    P3 --> P4[__main C库<br/>拷贝.data + 清零.bss + 建堆栈]
    P4 --> P5[Bootloader main<br/>bootloader_main.c]
    P5 --> P6[检查OTA标志 + 校验App]
    P6 --> P7[跳转 jump_to_app<br/>关中断+VTOR+设MSP+保留Thumb位]
    P7 --> P8[App 启动<br/>SystemInit→__main→App main]
    P8 --> P9[App main<br/>恢复中断+重定向向量表]
    P9 --> P10[外设初始化<br/>SysTick/USART0/I2C/TIMER1]
    P10 --> P11[while(1) 业务循环<br/>10ms姿态解算 + 周期上报 + 命令解析]
```

### 各阶段速查表

| 阶段 | 是谁干的 | 干什么 | 是硬件还是软件 |
|---|---|---|---|
| 上电自举 | CPU 内核 | 读向量表→设 MSP→跳 Reset_Handler | **硬件**（出厂固化） |
| 启动文件 | `startup_gd32f3x0.s`（汇编） | 调 SystemInit + __main | 软件 |
| 配时钟 | `SystemInit()` | 写 RCU 寄存器 → 84MHz | 软件（厂商库） |
| C 环境 | ARM C 库 `__main` | 拷 .data、清 .bss、建堆栈 | 软件 |
| 引导检查 | `bootloader_main.c` | OTA 标志 + App 校验 | 软件 |
| 跳转 | `jump_to_app()` | 关中断 + VTOR + 设栈 + BLX | 软件 |
| App 启动 | App 的启动文件 + main | 重走启动 + 恢复中断 + 外设初始化 | 软件 |
| 业务循环 | `main()` 的 while(1) | 10ms 姿态解算 + 上报 + 命令解析 | 软件（中断驱动） |

## 三、各阶段详解

### 第 0 步：上电（纯硬件，芯片出厂行为）

- **是什么**：电源稳定、复位释放后，Cortex-M4 内核自动自举。
- **怎么做**：
  1. 从 `0x00000000` 读**向量表（Vector Table）**第一个字 → 当作**主栈指针（MSP）**初始值；
  2. 读第二个字 → 当作**复位向量（Reset Vector）**（`Reset_Handler` 地址，带 Thumb 位）→ 跳过去。
- **为什么**：单片机没有引导程序，复位后 CPU 不知道代码在哪、栈在哪，全靠"固定位置放固定格式"（向量表前两个字）自举。这是 ARM 架构定的规矩，**不需要你写任何代码**。

> Bootloader 和 App **各有一份**向量表和启动文件，只是链接地址不同（BL 在 `0x08000000`，App 在 `0x08002000`）。

### 第 1 步：启动文件 `startup_gd32f3x0.s`（汇编）

`Reset_Handler` 里就 4 条关键指令：

```asm
LDR  R0, =SystemInit
BLX  R0            ; ① 调用 SystemInit 配时钟
LDR  R0, =__main
BLX  R0            ; ② 调用 __main，C 库初始化后进入 main()
```

- **① `SystemInit()`**：配置系统时钟。本工程：IRC8M（8MHz 内部 RC 振荡器）→ PLL 倍频 → **84MHz**。
- **② `__main()`**：把全局变量初值从 Flash 拷到 RAM（`.data`）、未初始化变量清零（`.bss`）、准备好栈/堆——**C 语言环境**才成立。

> 为什么 `main()` 不是程序真正的起点：C 代码假设"全局变量已在 RAM 且初值正确"，这个环境必须由汇编 + C 库在进 `main()` 前搭好。

### 第 2 步：Bootloader 的 main（`bootloader_main.c`）

| 顺序 | 代码 | 硬件层面干什么 |
|---|---|---|
| 1 | `usart_init()` | 使能 GPIOA/USART0 时钟，PA9/PA10 配 AF1，9600 波特率，使能收发 |
| 2 | `printf("[BL] ...")` | fputc 把字符塞进 `USART_TDATA`，移位寄存器发出 TX 引脚 |
| 3 | `ota_check_pending_upgrade()` | 读 Flash `0x0801F000` 魔数 `0xAA55AA55` |
| 4 | `is_app_valid()` | 读 App 向量表：栈顶在 SRAM？复位向量在 Flash 且 Thumb 位=1？ |
| 5 | `jump_to_app()` | 见下 |

**`jump_to_app()` 是整条链路最关键的一环，4 个硬件动作：**

```c
__disable_irq();                // ① 关全局中断：跳转途中不许来中断
SCB->VTOR = APP_START_ADDR;     // ② 向量表重定向到 0x08002000
__set_MSP(app_sp);              // ③ 栈指针换成 App 的栈
__set_PSP(app_sp);
void (*jump)(void) = (void(*)(void))app_pc;  // ④ 保留 Thumb 位
jump();                         // 本质是 BLX，跳 App 的 Reset_Handler
```

- ① 中断一来会读**当前**向量表，跳转中间读错就崩；
- ② App 的中断处理地址和 BL 不同，不重定向则 App 一进中断就跳到 BL 的 Handler；
- ③ App 的栈规划在它自己的地址，必须换；
- ④ Cortex-M 只执行 Thumb，`BLX` 看地址最低位决定状态——**bit0=1 才进 Thumb**（详见专题二）。

> 跳转后 **Bootloader 从此不再运行**（除非复位），只是把"接力棒"交给 App，类似 BIOS 引导操作系统。

### 第 3 步：App 的启动（热跳转，再走一遍启动文件）

跳转目标是 **App 自己的 Reset_Handler**，于是 App 重走：`Reset_Handler → SystemInit → __main → main()`。

**热跳转特有的坑**：App 的 `SystemInit` 默认会**再配一次 PLL**，但此刻时钟已是 BL 配好的 84MHz PLL，重配会让"PLL 就绪位"永远不置位 → 卡死。修复 = 加判断：**时钟源已经是 PLL 就跳过重配**。

```c
if ((RCU_CFG0 & RCU_CFG0_SCSS) != RCU_SCSS_PLL) {  // 热跳转时跳过
    ... PLL 配置 ...
}
```

### 第 4 步：App 的 main（`main.c`）——恢复环境 + 初始化外设

```c
int main(void) {
    SCB->VTOR = 0x08002000U;   // ① 再确认向量表指向 App 区
    __enable_irq();            // ② 恢复被 bootloader 关掉的中断
    systick_config();          // ③ SysTick → 1kHz（delay 基础）
    com_usart_init();          // ④ USART0 9600 + DMA + 空闲中断
    printf("[APP] started\r\n");
    hard_i2c_init();           // ⑤ I2C1: PA0/PA1 AF4, 100kHz
    imu_system_init();         // ⑥ 传感器初始化
    usart0_rx_dma_idle_init(); // ⑦ 串口 DMA 接收 + 空闲中断
    timer_config();            // ⑧ TIMER1 → 10ms 中断
    while (1) { ... }          // ⑨ 业务循环
}
```

- **③ SysTick**：内核自带 24 位递减定时器，1ms 中断 → `SysTick_Handler` 里 `delay_decrement()` 给延时函数倒数。
- **④/⑦ USART0 接收**：接收走 **DMA（直接内存访问）**，字节进内存不占 CPU；靠**空闲中断（IDLE）**判断"一帧收完"，在 `USART0_IRQHandler` 里算长度、置 `usart0_rx_flag`。发送走 DMA_CH1 + 完成中断清 busy。
- **⑤ I2C1**：PA0/PA1 配 AF4，100kHz，接 ICM42670(0x68)、QMC5883P(0x2C)。
- **⑥ `imu_system_init()`**：ICM42670 用软 I2C 写配置 → 恢复 AF4；QMC5883P 初始化；加载零点/报警参数/断电前航向。
- **⑧ `timer_config()`**：TIMER1 预分频 8400、周期 100 → `84MHz/8400/100 = 100Hz = 10ms` 更新中断 → 置 `imu_loop_flag`。**这是业务循环的"心跳节拍器"。**

### 第 5 步：`while(1)` 业务循环

```c
while (1) {
    if (imu_loop_flag) {          // TIMER1 每 10ms 置 1
        imu_loop_flag = 0;
        imu_main_loop(12);        // 采数据 + 姿态解算 + 报警 + 存航向
        debug_cnt++;
        if (debug_cnt % 1000 == 0)        proto_send(0x82);  // 每10s 角度
        else if (debug_cnt % 1000 == 500) proto_send(0x8E);  // 每5s 心跳
    }
    if (usart0_rx_flag) {         // USART0 空闲中断置 1
        usart0_rx_flag = 0;
        ... 按功能码分流 OTA / 业务，校验通过则 proto_send ...
    }
}
```

- `while(1)` 本身永远转，但**大部分时间什么都不干**——工作靠两个中断"唤醒"：
  - **TIMER1 更新中断**每 10ms 置 `imu_loop_flag` → 跑一帧姿态解算；
  - **USART0 空闲中断**每收到一帧置 `usart0_rx_flag` → 解析命令并回帧。
- **为什么用中断+轮询**：姿态解算要**固定节拍**（100Hz），用硬件定时器最准；串口交给 DMA 不占 CPU，主循环只在"有活干"时处理。

## 四、专题一：SystemInit 是软件还是硬件？

### 结论

**是软件（固件库代码），不是硬件。** 它是普普通通的 C 函数，由汇编启动文件在 `Reset_Handler` 里点名调用。硬件是它**去操作的那些寄存器**。

### 硬件干的 vs 软件干的

| 环节 | 是硬件还是软件 | 谁干的 |
|---|---|---|
| 上电自动读向量表、设 MSP、跳 Reset_Handler | **硬件**（芯片内部固化逻辑） | CPU 内核 |
| 调用 SystemInit | **软件**（汇编 3 条指令） | `startup_gd32f3x0.s` |
| SystemInit 配时钟 | **软件**（C 函数） | `system_gd32f3x0.c` |
| 寄存器被写后真正输出 84MHz | **硬件**（RCU 时钟电路） | RCU 寄存器 |

### 实际代码（`system_gd32f3x0.c` 第 235 行起）

```c
void SystemInit(void) {
    ...
    if((RCU_CFG0 & RCU_CFG0_SCSS) != RCU_SCSS_PLL) {   // 热跳转时跳过
        RCU_CTL0 |= RCU_CTL0_IRC8MEN;                  // ① 打开内部 8MHz 振荡器
        while(0U == (RCU_CTL0 & RCU_CTL0_IRC8MSTB)) {} // ② 等它稳定
        ...
        system_clock_config();                         // ③ 配 PLL → 84MHz
    }
    nvic_vector_table_set(NVIC_VECTTAB_FLASH, VECT_TAB_OFFSET);  // ④ 设向量表位置
}
```

一句话：**往 RCU（Reset and Clock Unit，复位与时钟单元）寄存器写值**——"用 8MHz 内部振荡器 → 经 PLL 倍频 → 输出 84MHz → 分频给 AHB/APB 总线"。

类比：硬件是"发动机"，寄存器是"挡位旋钮"，`SystemInit` 是"司机"。

### 关键点

1. **它是软件，会编译进你的固件**，烧进 Flash 随固件运行；你不动它，它也在。
2. **它是芯片厂商（GigaDevice）写好的**，属于 CMSIS 标准固件库源码，可以查看甚至修改（本工程的 `SCSS==PLL` 判断就是为热跳转加的）。
3. **为什么必须配时钟**：上电默认跑慢的内部 8MHz；而串口波特率、TIMER1 10ms、I2C 速率全按 84MHz 推算。不配到 84MHz，所有外设时序全错。
4. **与"硬件启动"的分界**：读向量表、跳 Reset_Handler 是硬件自带行为，无需代码；从 Reset_Handler 之后**每一步都是软件**。Bootloader 和 App **各跑一次** SystemInit。

## 五、专题二：Thumb 指令集是谁指定的？

### 结论

**Thumb 是一种指令集（Instruction Set Architecture，ISA）——"CPU 能看懂哪种机器码"的语言规范。** 指定它的是**三层**：硬件架构（根本）→ 编译器（编译时）→ CPU 状态位 + 跳转地址最低位（运行时）。

### 第 1 层：机器码和指令集

- C → 编译器 → 汇编指令 → **机器码**（0/1 串）。
- CPU 按"字典"解码执行，这本字典就是**指令集**——规定每条 0/1 组合代表什么操作。
- **Cortex-M4 硬件只内置了 Thumb 指令集**（M = Microcontroller，为高代码密度设计）。这是芯片设计时焊死的行为，**软件无法更改**。

### 第 2 层：编译时——编译器生成 Thumb 机器码

因为目标是 Cortex-M4，编译器（Keil ARMCC）默认用 **Thumb/Thumb-2 模式**生成机器码（16 位或 32 位编码）。老的 ARM 指令是 32 位，Cortex-M 根本不会执行。

### 第 3 层：运行时——谁告诉 CPU"现在是 Thumb"？

CPU 内部有**状态寄存器 CPSR**（Current Program Status Register），其中 **T 位（Thumb 标志位）=1 表示按 Thumb 解码**，=0 按 ARM 解码。

**执行跳转指令 `BX`/`BLX` 时，CPU 看目标地址的最低位（bit0）：**

```
目标地址 bit0 = 1  → T=1，切到 Thumb 状态（正确）
目标地址 bit0 = 0  → T=0，切到 ARM 状态（Cortex-M 上必崩）
```

这就是为什么向量表里的复位向量必须是**奇数**（`0x08002165`）——真正指令地址是 `0x08002164`，最低位的"1"**不是地址的一部分，而是 Thumb 状态标记**。

### 项目踩坑案例

```c
// ❌ 之前跳转代码写成：
(void (*)(void))(app_pc & ~1U);   // 把 bit0 清了 → CPU 切 ARM 状态
                                   // 去解码 Thumb 机器码 → 立即 HardFault

// ✅ 正确：
(void (*)(void))app_pc;           // 保留 bit0=1 → 进入 Thumb → 正常执行
```

**整个链路**：硬件（Cortex-M 只支持 Thumb）→ 编译器（生成 Thumb 机器码）→ 链接器（向量表里复位向量标成奇数）→ 跳转时 CPU 读 bit0 设 T 位 → 按 Thumb 解码执行。任何一环断了，CPU 就用错"字典"，瞬间崩溃。

## 六、总结与自查

### 一句话串起来

- **SystemInit**：软件写寄存器配时钟 → 硬件才跑 84MHz。
- **Thumb**：硬件"只认这一种指令字典" → 编译时按它生成机器码 → 运行时靠 T 位/bit0 保持一致。

### 自查清单（能答上就说明懂了）

1. 上电后 CPU 凭什么知道第一条指令在哪？（向量表）
2. `main()` 之前谁把 C 环境搭好？（`startup_gd32f3x0.s` + `__main`）
3. 跳转时为什么必须先 `__disable_irq()` 再设 `SCB->VTOR`？（防止中断读错向量表）
4. `SystemInit` 是硬件吗？（不是，是写寄存器配置时钟的软件）
5. 为什么复位向量必须是奇数？（BLX/BX 用 bit0 设 CPSR.T，=1 才是 Thumb）
6. 业务循环靠什么驱动？（TIMER1 10ms 中断 = 节拍，USART0 空闲中断 = 耳朵，DMA = 搬运工）
